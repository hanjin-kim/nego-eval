# nego-eval

一个由智能体**自己挑选**交易对手、并且**会再次遇到**同一个对手的谈判环境。

允许智能体挑选对手的谈判基准，会在一局结束时丢掉记录；保留记录的基准，则替它指定对手。
于是构成一段关系的东西——你自己选的那个人，上一次发生了什么——从来没有当过变量。

在这里它就是变量，而且只有一个比特。

|  | 自选对手 | 跨局记忆 |
|---|---|---|
| [Cattle Trade](https://arxiv.org/html/2605.14537v1) | 是 | 否 |
| [M3-Bench](https://arxiv.org/pdf/2601.08462) | 固定双方 | 仅局内 |
| [RLVR negotiation](https://arxiv.org/abs/2604.09855) | 只有一个卖方 | 否 |
| **nego-eval** | **是** | **是** |

---

## 这个游戏

三个卖方公开报价。买方每回合买一件。交付有时会失败，失败就产生损失 `L`，而只有当
**两个整数相加等于它**时这一回合才结算：

```
L_买方 + L_卖方 = L
```

双方就这个分摊最多来回三次。如果始终谈不拢，损失就留在它落下的地方——买方身上——并且
这一对停止交易三个回合。开始之前双方都被告知这一点，这正是卖方肯让步的理由。所有金额
都落在 10 的格点上，所以 `L = 110` 时合法的分摊恰好有十二种。

一场**比赛**是与同样三个卖方进行的 12 回合 × 4 局。被操纵的变量是：每一局开始时是带着
整场比赛的账本，还是从陌生人开始。两种条件下的随机种子、卖方阵容、规则和长度完全相同。

### 什么被公示，什么不被公示

| | 在哪里 | 是否计入价格 |
|---|---|---|
| 对无往来买方的交付率 | 报价单上，精确值 | 是 |
| 对陌生买方承担的损失比例 | 只有失败过才知道 | 否 |
| 对老客户会多承担多少 | 只有留下来才知道 | 否 |

供应商的准时交付率写在目录里，你为它付钱。货毁了之后它会做什么，目录里没有，合同也强制
不了，只有亲身遇到才知道。这一切都以整数计数，所以奖励是算术——**回路中任何位置都没有
裁判模型。**

## 它类比的是什么

每一条机制都对应买方真实会做的事，值得把对应关系写清楚——一个什么都不像的桌游是谜题，
不是环境。

| 游戏中 | 采购中 |
|---|---|
| 公示的交付率，以及更高交付率对应的更高价格 | 准时交付率、质量认证、SLA 等级——公示的，且要为它付钱 |
| 交付失败时的损失 | 间接损失：停线、加急运费、没做成的销售、返工 |
| 相加必须等于损失的两个整数 | 总有人承担。合同对间接损害通常沉默，而沉默把它推给买方 |
| 围绕分摊的三次来回 | 事故之后的那通电话——折让单、免费补货、运费对半 |
| 谈崩：买方全担，且这一对停止交易 | 谈不拢，自己吃下，然后下一次询价名单上没有这家 |
| 对陌生买方承担的损失比例 | 目录里没有。要有一批货毁了才知道 |
| 对老客户会多承担多少 | 新账户和十年账户之间那条没有写下来的差别 |
| 跨局带过来的账本 | 一份跨越财年、合同续签、或者采购换人的历史 |
| 每回合抖动的价格 | 现货波动。某些周留在原供应商那里要多付这个差额，这才使"留下"成为一个决定 |

表格正中的那个不对称才是重点，而且不是这里发明的。供应商公示的东西已经算进它的报价；
出事之后它做什么，既不公示也不可缔约，只能靠遇到才知道。这个缺口正是
[Brown, Falk & Fehr](https://onlinelibrary.wiley.com/doi/abs/10.1111/j.1468-0262.2004.00511.x)
放进实验室的东西，也是 Macchiavello 与 Morjaria 在真实供应链里测量的东西：关系之所以在
那里形成，是因为合同够不着的那部分，别的什么也强制不了。

### 对智能体来说，"没有跨局记忆"不是假设

这个操纵还有第二种读法，完全不需要供应链。**一个新的上下文窗口就是一个没有往来记录的
买方。** 新会话也是，丢掉了账本的摘要转录也是，只返回当前报价的工具调用也是。这个环境
切换的那个条件，正是智能体系统默认所处的条件，而这里测量的是它的代价。

### 类比在哪里失效

写出来，是因为读者反正会发现，最好在这里先发现。

- **三个卖方不是一个市场。** 没有进入、没有退出，也没有买方之间争夺优质供应商注意力的
  竞争。
- **单一品类，每回合一件。** 没有组合采购、没有交期、没有质量等级、没有起订量。
- **失败是外生的，而且其概率被公示。** 现实中两者都不成立：可靠性会随供应商被如何对待
  而变化，而且没人会诚实地公示它。
- **破产机制被关掉了。** 被压到成本线以下的真实供应商会偷工减料，然后消失。那套机制在
  更早的一版里有，这里因为下文给出的测量原因关掉了；这是一处真实的缺失。
- **没有法院、没有保险、没有 Incoterms。** 间接损失在真实合同里常常**事先**就分配好了。
  这块板对应的是没有事先分配的那种情形。
- **时间视野是已知的。** 智能体被告知还剩多少回合，这会以开放式关系中不会发生的方式，
  强化终局行为。

## 快速开始

```bash
pip install -e ".[dev]"
pytest                                   # 34 项不变量测试，不需要 API key

python scripts/run_carry4.py             # 被操纵的变量，脚本化策略
python scripts/run_dp4.py                # 用动态规划求出的精确最优
python scripts/train_rl4_shaped.py       # 表格 Q 学习，两种奖励整形
```

只有语言模型买方需要 key，其余都不需要。

```bash
cp .env.example .env && $EDITOR .env
python scripts/run_probe4.py             # 每个冻结局面走一步
python scripts/run_fullplay4.py "[('deepseek/deepseek-chat', 12)]" on
python scripts/run_fullplay4.py "[('deepseek/deepseek-chat', 12)]" off 910012
python scripts/analyse_paired4.py        # 相同种子下，模型对参照
```

第三个参数是起始种子，因此一条实验臂会从上一次停下的地方接着跑，而不是重放已经付过钱的
比赛。

## 参照点

在 `L = 110`、12 回合 × 4 局、溢价 120 的设定下：

| 策略 | 得分 | 占关系性剩余的比例 |
|---|---|---|
| 最优，动态规划 | **1099** | 100% |
| 无跨局记忆时的最优 | 1031 | 59% |
| 手写规则，读账本 | 996 | 38% |
| 手写规则，只读报价单 | 934 | 0% |
| 表格 Q 学习，剩余奖励 | 898 | — |

以及模型打完整场比赛、在相同种子上与这些参照配对的结果。零点是那条手写规则，每一个模型
都在它左边。

| 模型 | n | 得分 | 相对规则 | 相对只读报价单 |
|---|---|---|---|---|
| gpt-5.6-terra | 12 | 958 | −127 ±68 | +6 ±75 |
| gpt-5.6-sol | 10 | 897 | −153 ±75 | −27 ±96 |
| claude-fable-5 | 10 | 876 | −174 ±63 | −48 ±82 |
| gemini-3.7-flash | 24 | 762 | −118 ±35 | −66 ±34 |
| qwen3.8-max | 8 | 786 | −251 ±101 | −190 ±105 |
| claude-haiku-4.5 | 12 | 663 | −421 ±72 | −288 ±79 |
| deepseek-chat | 12 | 610 | −474 ±87 | −342 ±91 |

配对比它看上去更要紧。单场比赛的离散度是两百到六百，而早期有一个种子对一个完全不查账本
的策略也值 +530——所以拿模型的均值去比在别的种子上算出来的参照均值，量到的主要是抽到了
哪些局面。

剩余的分母是 `1099 − 934 = 165`：把账本读到完美时它值多少。总利润不适合作为这个环境的
尺度，因为其中大约 85% 来自用合理的价格买东西，而这件事任何像样的策略都做得差不多好。

**最优是可计算的。** 卖方的让步只取决于买方在最近八个回合中占的比例，交付率是公示的，
价格是每个种子固定的序列——所以状态就是 `(回合, 最近八次选择)`，值迭代能精确解出。很少
有环境能报告真正的天花板，而不是"目前已知的最好成绩"。

## 那份契约

在有一块板可用之前失败了三块，而且各自失败得不一样。所以这些条件是一个模块——
`nego_eval.game.contract`，可以对任何候选板运行；每一条都是测量，不是指导原则。

| 条件 | 阈值 | 为什么 |
|---|---|---|
| 答案可从提示中还原 | ≥ 0.95 | 否则这是噪声下的估计任务，任何分数都无法对照天花板来读 |
| 光看报价单解决不了 | ≤ 0.75 | 否则账本只是装饰 |
| "失败最少的那个"不是陷阱 | ≥ 0.45 | 一个让平常启发式只拿到随机分的板，量的是对作者的顺从，不是能力 |
| 没有任何单一启发式够用 | ≤ 0.80 | |
| 不能靠名字猜中 | ≤ 0.42 | |
| 还价能争取到东西 | = 1.00 | 如果开价已经是上限，就不存在可以失败的谈判 |

先前那三块板**不在**这个仓库里。每一块的撤回理由，如今都写进了对应的条件；而发布一个装
着四块板、其中三块是错的包，只会诱使别人在错的那块上继续搭。`table4.py` 就是那块板。被
丢掉的是什么、各自错在哪里，写在 `notes/` 里。

### 清单装不下的那一条

第三块板满足了每一条可测量的条件，量的却仍然是错的东西：为了让公示交付率精确，关掉了忠
诚度改善交付的通道；为了恢复还价空间，让步上限里的忠诚度项又失去了约束力；两者之间，
**再没有任何途径让"回头找同一个卖方"使那个卖方变得更好。** 剩下的只是一个固定的隐藏属性
和一个把它查出来的买方。于是带着账本跨局只省了时间，几乎没有别的——而它量到的恰恰就是
这个。

在冻结局面上算出的任何数字都抓不到这一点。得去读一份对局记录。

## 目前已知的结论

除非另有说明，都是在这块板上测得的。完整记录见 `notes/note.html`，其中也包括早先修订版
搞错的五个数字。

**带着账本跨局的价值，等于关系需要多久才能建立、与它多快被打断之间的差额。** 把总回合数
固定在 48、只移动边界的位置，这个价值从 4 局时的 +61 单调升到 24 局时的 +181。有记忆时
分数是平的；没有记忆时，每一局都要重新开始一段还没长到能回本就结束的关系。

  <source media="(prefers-color-scheme: dark)" srcset="docs/shape.dark.svg">
  <img alt="随着边界增多，跨局带账本的价值" src="docs/shape.light.svg">
</picture>

**把记录交给一个并非围绕它构建的智能体，比不给还糟。** 一个在没有跨局记忆的条件下训练的
表格策略，在测试时拿到跨局账本，开局选对的比例是 0.14——而随机是 0.33。它的查表有三分之一
落在训练从未到过的状态，其余状态的访问次数中位数是 178，对比它熟悉的状态是 55,161。同样的
形状还出现了两次：把预先算好的比率追加到账本上，让一个模型掉了 0.15，并且瓦解了它本来在
用的那一列；而下面七个模型里有六个，在账本存在之后选得比之前更差。

**从奖励中减去与关系无关的基线，价值 +49**——对一个其余完全相同的学习器而言。这个控制变量
拿掉了信号里那已经被解决的 85%。

**七个语言模型打了完整比赛，其中六个在账本到来之后选得更差。** 把第二局及以后的开局选择
与第一局的开局选择相比：qwen3.8-max 从 0.88 掉到 0.29，低于 0.33 的随机水平——而它为此每场
花了一小时；claude-fable-5 从 0.70 到 0.47；另外三个略有下滑。**只有 gemini-3.7-flash 上升，
从 0.29 到 0.61**，而在没有历史可读时它是七个里最差的。手写规则是从 0.52 到 0.71。

<picture>
  <source media="(prefers-color-scheme: dark)" srcset="docs/ledger.dark.svg">
  <img alt="账本存在之前与之后的开局选择" src="docs/ledger.light.svg">
</picture>

**每一个模型都输给那条规则**，在相同种子上配对后差距为 118 到 474，至少两个标准误。而对
那个更弱的参照——完全不查账本的策略——只有垫底的两个明显落后，所以"前沿模型的分数低于零
假设"**并不是**这里展示的结论。

**规模预测不了其中任何一项。** 唯一被账本帮到的是 flash 档的模型；被测量的两个顶级档模型
分别落在中游和末位。同一家族中跨世代、跨规模的三个模型，在同一个探针上得到 0.48 / 0.47 /
0.46。

**模型是否真能从跨局带账本中获益，目前仍未定。** 一个模型在 35 个共享种子上跑了两种条件：
+40 ±35，而环境对一个完美使用它的策略给出的是 +64。与两者都相容，与任何一方都区分不开。
在 16 对时，同一个测量读出 +88 ±43，看上去已成定论；并没有。

## 目录结构

```
src/nego_eval/
  sim/       世界、议价、智能体、学习到的基线、LLM 客户端
  game/      板、金额格点、比赛运行器、契约
scripts/     记录里的每一项测量，一项一个文件
data/        那些脚本产出的数字
tests/       34 项不变量——16 项关于结算规则，18 项关于游戏
notes/       记录
```

每个模块的 docstring 都写着它长成这样之前出过什么错。这是有意的：这里的设计大部分是疤痕，
而疤痕正是值得读的那部分。
